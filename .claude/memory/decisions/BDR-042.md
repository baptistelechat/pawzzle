# BDR-042 — Son de dialog centralisé sur `onOpenChange`, pas de prop générique sur `Button`

| Décision                                                                                                                                                                                                                     | Pourquoi                                                                                                                                                                                                                                                       | Alternatives considérées                                                                                                                                                                                                                                                                                                                 | Statut |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Le son/haptique d'ouverture-fermeture des modals (`menu_open`/`menu_close`) est déclenché une seule fois, dans `onOpenChange` du composant `Dialog` partagé (`src/components/ui/dialog.tsx`), pas via une prop sur `Button`. | `RulesDialog`, `SettingsDialog` et `WelcomeDialog` passent tous par ce même `Dialog` — un seul point de branchement couvre les 3 triggers sans dupliquer `sounds.play()`. Ces trois triggers en étaient dépourvus avant ce fix, symptôme signalé par Baptiste. | Prop `sound`/`withSound` générique sur `components/ui/button.tsx` — écartée : ne distingue pas les sémantiques (`ui_click` vs `ui_toggle` vs `menu_open`/`menu_close`), risquerait un double son sur les callers qui appellent déjà `sounds.play()` manuellement, et ne couvre de toute façon pas la grille de jeu (pas des `<Button>`). | actif  |
