# BDR-002 — Roadmap MVP en 4 phases séquentielles avec gate de validation

**Décision** : Roadmap MVP structurée en 4 phases séquentielles (setup projet → moteur de règles/génération → UI minimale → test interne), avec une Phase 4 "hors scope" explicitement listée (formes non carrées, contraintes échecs, Supabase, PWA, LP/SEO) et un gate bloquant : ne pas commencer la Phase 4 sans validation utilisateur de la Phase 3

**Pourquoi** : Le brief (section 8) impose un ordre de validation strict — prototyper et valider le gameplay avant tout développement de sauvegarde/distribution. Formaliser ce gate en roadmap évite la dérive naturelle vers "juste ajouter Supabase en même temps"

**Alternatives considérées** : Roadmap unique sans phase de gate explicite — écartée, risque de complexifier le projet avant validation du fun
