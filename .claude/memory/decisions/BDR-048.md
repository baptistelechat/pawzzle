# BDR-048 — Geste/bouton retour ferme les dialogs plutôt que de naviguer hors de l'app

**Décision** : Le `Dialog` partagé (`src/components/ui/dialog.tsx`) pousse une entrée d'historique factice à l'ouverture et l'écoute via `popstate` pour fermer le dialog (`actionsRef.close()`) au lieu de laisser le navigateur naviguer hors de l'app. `history.scrollRestoration = "manual"` réglé une fois au démarrage (`main.tsx`).

**Pourquoi** : Centralisé dans le `Dialog` partagé (même pattern que le son, [BDR-042](BDR-042.md)) — couvre WelcomeDialog/RulesDialog/SettingsDialog d'un coup. `scrollRestoration=manual` évite que Chrome tente de restaurer un état sur des entrées d'historique qui ne correspondent à aucune vraie navigation.

**Alternatives considérées** : Gérer le `popstate` par dialog individuellement (écarté, duplication). Ne pas gérer le retour du tout (écarté, demande explicite de Baptiste).
