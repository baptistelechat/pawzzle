# LRN-026 — `vite preview` n'écoute pas le réseau, même si le script `dev` a `--host`

| Pattern observé                                                                                                                                                                                                                          | Contexte                                                                                                                                                                                           | Application future                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le flag `--host` est posé une fois dans le script `dev` du `package.json` et n'a plus jamais à être retapé — mais `preview` est un script distinct, sans le flag, qui ne bind donc que `localhost`. L'asymétrie est invisible à l'usage. | Test d'un build sur mobile : `https://<ip-lan>:4173` répondait sur le PC (via localhost) mais restait injoignable depuis le téléphone du même réseau, alors que `pnpm dev` marche depuis toujours. | Devant un serveur de dev injoignable depuis un autre appareil du LAN, lire le script réellement lancé dans `package.json` **avant** de suspecter le pare-feu, le sous-réseau ou le TLS. Fix : `pnpm preview --host`. |

Hypothèse écartée : certificat mkcert non approuvé sur le téléphone. Le mécanisme est réel (`vite-plugin-mkcert` écrit `server.https` **et** `preview.https`, donc le preview est bien en HTTPS avec un CA local), mais ce n'était pas le vecteur du blocage ici — un diagnostic plausible et vérifiable dans le code du plugin peut rester la mauvaise cause.
