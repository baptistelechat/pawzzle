# LRN-009 — `AnimatePresence mode="wait"` se bloque si l'état bascule 3× plus vite que la transition

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Contexte                                                                                                                                                                                                                                                                                                                                           | Application future                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cliquer "Nouvelle partie" fait passer `status` `playing→loading→playing` en quelques ms (le Worker répond quasi instantanément). `AnimatePresence mode="wait"` (qui attend la fin de la sortie de l'élément N avant de monter l'élément N+1) reçoit un **3ᵉ** changement d'enfants avant d'avoir fini de résoudre le 2ᵉ. Résultat : le state machine interne ne récupère jamais — `setLevel`/`setStatus("playing")` s'exécutent bien (confirmé par logs), le DOM ne remonte jamais le contenu "level". Spinner bloqué indéfiniment, **aucune erreur console**, 100% reproductible dès qu'une transition va-et-vient plus vite que sa propre durée. Symptôme initialement mal diagnostiqué comme "bug du générateur de niveau" ou "spécifique mobile" — en réalité reproductible en Chrome headless dès le premier essai. | Pawzzle — `App.tsx`, plan d'animation 003 (transition spinner↔contenu de niveau). `mode="wait"` avait été choisi délibérément dans le plan écrit à l'avance ("ici ce n'est pas le bug LRN-005, un léger wait est imperceptible") — mais ce raisonnement ignorait la fréquence réelle : le worker répond plus vite que les 150-300ms de transition. | Ne jamais utiliser `mode="wait"` pour un état qui peut faire un aller-retour (A→B→A) plus vite que la durée de transition — préférer `mode="popLayout"` (pas de file d'attente séquentielle, gère les interruptions). Toujours donner un `exit` explicite à CHAQUE enfant d'`AnimatePresence`, même celui qu'on pense "jamais retiré vite". Pour diagnostiquer un spinner bloqué sans erreur console : logger `setState` + `onmessage` d'abord (élimine la couche logique), PUIS vérifier le DOM réel (`document.querySelectorAll`) pour voir si le contenu existe mais reste cru manquant — ça pointe direct vers la couche animation/rendu plutôt que la couche données. |
