# LRN-20260823183009-3 — Une demande de libérer un port ne doit jamais être suivie d'une relance automatique

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                              | Contexte                                                                                                                                                                              | Application future                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Baptiste a explicitement demandé de tuer le process sur le port 5173 pour relancer le serveur lui-même. Un peu plus tard dans la même session, un réflexe de vérification visuelle ("lancer le dev server avant de déclarer terminé") a fait relancer un serveur Vite sur ce même port — contredisant directement la demande initiale, détecté et corrigé immédiatement sur signal du système (pas par relecture spontanée). | Règle générale "démarrer le dev server pour vérifier visuellement une UI" appliquée sans relire les instructions récentes du fil de conversation qui la contredisaient explicitement. | Une instruction explicite de l'utilisateur sur une ressource partagée (port, process, fichier verrouillé) prime toujours sur une règle de workflow générique — vérifier le fil récent avant toute action qui pourrait la recréer, même indirectement (ex: lancer un serveur pour "juste vérifier"). |
