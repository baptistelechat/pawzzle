# LRN-008 — Web Worker sans gestion d'échec : une exception non catchée bloque le spinner indéfiniment (visible surtout mobile)

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Contexte                                                                                                                                                                                                                                                                                                                                           | Application future                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateLevel` (backtracking + rejet, garde-fou `MAX_ATTEMPTS = 1000`) peut lever une exception si aucune grille à solution unique n'est trouvée. Dans le worker, cette exception n'était jamais catchée : `self.postMessage` n'était jamais appelé, `worker.onmessage` côté main thread ne se déclenchait donc jamais, et le `status` restait bloqué sur `"loading"` pour toujours — seul un rechargement complet de la page (nouveau Worker) en sortait. Signalé par Baptiste comme "sur mobile ça charge indéfiniment, sur PC ça marche" — probablement une variance aléatoire du taux d'échec plus visible/fréquente sur un CPU plus lent, pas un bug spécifique à la plateforme. | Pawzzle — bouton "Nouvelle partie"/"Rejouer" (`useLevel.ts` + `generateLevel.worker.ts`). Fix : le worker renvoie désormais `{ ok: true, level }` ou `{ ok: false }` (try/catch autour de `generateLevel`), et `worker.onmessage` relance automatiquement `postMessage` avec un nouveau seed si `ok: false`, au lieu de laisser le spinner mourir. | Tout Worker qui peut échouer côté logique métier (pas seulement crasher) doit renvoyer un résultat typé succès/échec explicite, jamais laisser une exception se perdre silencieusement — le thread principal ne peut réagir qu'à ce qui lui est effectivement posté. Pour un générateur à rejet (rejection sampling), prévoir la reprise automatique côté message-handler plutôt qu'un simple throw. |

## Correction (2026-07-21, plus tard dans la même session)

Ce fix reste une bonne pratique défensive (un Worker ne doit jamais laisser une exception se perdre), **mais ce n'était PAS la cause du bug réellement signalé** ("Nouvelle partie" bloqué en boucle). Reproduit ensuite en Chrome headless (donc pas mobile-spécifique) : le générateur répondait correctement (`ok: true` confirmé par logs), le vrai coupable était `AnimatePresence mode="wait"` dans `App.tsx` qui se bloquait sur des transitions trop rapides. Voir [LRN-009](LRN-009.md) pour la vraie cause et le vrai fix.
