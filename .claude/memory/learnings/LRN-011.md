# LRN-011 — Une clé statique d'`AnimatePresence` ne remonte jamais si l'async résout plus vite qu'un rendu observable

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Contexte                                                                                                                                                                                                                                                                                                                                                  | Application future                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Composant animé démonté/remonté via un toggle d'état dérivé (`status === "loading" ? <Spinner key="loading"/> : <Content key="level"/>`) : si l'opération async pilotant ce toggle (Worker, fetch) se résout plus vite qu'un cycle de rendu réellement peint, React ne commet jamais visiblement l'état intermédiaire — la clé "finale" ne change donc jamais du point de vue d'`AnimatePresence`. Le composant ne remonte JAMAIS : ses enfants reçoivent seulement de nouvelles props, sans exit ni enter. Confirmé par `MutationObserver` (0 mutation DOM) et échantillonnage d'opacité `requestAnimationFrame` en direct — pas par lecture de code, le state React reste correct tout du long, ce qui rend le bug invisible depuis les logs. | Pawzzle — suite de [ZBLK-008](../archive/blockers/ZBLK-008.md) (qui avait évité le blocage total via `mode="popLayout"`) : repasser à `mode="wait"` pour tenter une animation de sortie séquentielle a fait réapparaître le même mécanisme, cette fois sans blocage visible — juste sans animation du tout ([ZBLK-009](../archive/blockers/ZBLK-009.md)). | Clé un composant animé par une valeur qui change EN MÊME TEMPS que les données elles-mêmes (ex: compteur `levelId` incrémenté à la réception), dans sa propre `AnimatePresence` dédiée — jamais par un état "loading"/spinner dérivé d'une opération async dont la vitesse n'est pas maîtrisée. Voir [BDR-015](../decisions/BDR-015.md). |
