# LRN-019 — `.play()` différé par `setTimeout` après un tap : symptôme résolu, mécanisme exact non confirmé

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Contexte                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Application future                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Même symptôme que [LRN-018](LRN-018.md) (l'`<audio>` "démarre" — `isPlaying: true`, `currentTime` avance visiblement dans l'UI — mais reste inaudible), causé cette fois par un `window.setTimeout(() => ambient.play(), 300)` déclenché dans un handler de clic. Reproductible uniquement sur mobile (Android/Chrome confirmé par Baptiste), pas sur desktop. **Hypothèse initiale erronée** : d'abord attribué à la règle iOS Safari de perte du geste utilisateur (GLRN-222) — invalidé, l'appareil de test était Android, pas iOS. Le mécanisme exact du délai `setTimeout` sur Android reste donc non confirmé (piste la plus probable : une variante du race `requestAnimationFrame`/`.play()` de [LRN-018](LRN-018.md), non ré-instrumentée en direct pour le confirmer). | Changement manuel de piste ambiance (`goToAmbientTrack` dans `src/lib/sounds.ts`, [BDR-017](../decisions/BDR-017.md)) : fondu sortant de 300ms puis `window.setTimeout(() => loadAmbientTrack(track), 300)` pour swapper la piste — le tout premier chargement (appel direct, sans `setTimeout`) fonctionnait ; tous les changements suivants (bouton suivant/précédent) échouaient silencieusement sur mobile. Supprimer le `setTimeout` et appeler `loadAmbientTrack` directement dans le tick du clic a résolu le problème (confirmé par Baptiste après test réel). | Face à un symptôme de ce type (lecture "active" mais muette) sur mobile, ne pas citer une cause précise (ex. règle navigateur spécifique) sans l'avoir vérifiée sur le navigateur/OS réellement utilisé — demander ou confirmer la plateforme avant de diagnostiquer. En correctif, éviter par défaut de différer un `.play()` (ou un fondu qui en dépend) via `setTimeout`/`requestAnimationFrame` en réaction à un tap/clic : l'appeler directement dans le même tick que le handler. |
