# BLK-032 — Scrollbar verticale sur mobile après l'épinglage du footer

| Friction                                                                                                                                     | Cause réelle                                                                                                                                                                                                                                                                                                                     | Solution                                                                                                                                                                                                                                                      | Statut |
| -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Une fois la pill rendue visible par le `sticky` ([BDR-038](../decisions/BDR-038.md)), Baptiste a signalé une scrollbar verticale sur mobile. | Le `sticky` n'a jamais réduit la hauteur du document : l'élément reste dans le flux ([LRN-027](../learnings/LRN-027.md)). Le débordement de quelques pixels diagnostiqué en [ZBLK-030](../archive/blockers/ZBLK-030.md) était donc toujours là — simplement rendu perceptible au lieu d'être masqué sous la ligne de flottaison. | Plafonner le bloc de niveau par un budget de hauteur dérivé de `100dvh`, pour que la grille rétrécisse au lieu de pousser la page ([BDR-039](../decisions/BDR-039.md)). Le `sticky` est conservé en filet si le budget est sous-estimé sur un appareil donné. | résolu |

Statut ouvert : `pnpm lint` et `pnpm build` sont verts, mais le comportement n'est pas encore confirmé sur appareil. Deux points à vérifier — plus aucun scroll sur mobile barre d'URL déployée, et **grille inchangée sur desktop** (seul endroit où le budget de 19rem pourrait déborder).

**Amendement du 2026-07-25** — Baptiste a signalé que le scroll réapparaît spécifiquement en mode PWA installé (pas de barre d'URL du tout). Cause étendue : en standalone, `100dvh` n'exclut pas la zone sous l'encoche/l'indicateur d'accueil — jamais comptée dans le budget de 19rem, masquée jusqu'ici par la marge que donnait la barre d'URL du navigateur. Fix : `viewport-fit=cover` sur le meta viewport + `env(safe-area-inset-top)`/`env(safe-area-inset-bottom)` soustraits en plus dans le calc de [BDR-039](../decisions/BDR-039.md), et padding de sécurité équivalent sur le footer épinglé. Statut inchangé à ce stade : le périmètre à confirmer sur appareil couvre désormais navigateur mobile **et** PWA standalone.

**Résolu le 2026-07-25** — après l'échec d'une tentative de reconstruction flex/`aspect-ratio` ([BLK-033](../blockers/BLK-033.md)), Baptiste a demandé de ramener la contrainte au niveau de l'app entière plutôt qu'un calcul par élément : `h-dvh overflow-hidden` sur la racine ([BDR-040](../decisions/BDR-040.md), qui remplace [BDR-039](../decisions/BDR-039.md)). Le symptôme rapporté ici — une scrollbar — est désormais structurellement impossible (`overflow-hidden` est inconditionnel), donc résolu par construction. Le risque résiduel (rognage visuel sur écran très court) est un mécanisme différent, accepté sciemment, pas suivi comme blocage.
